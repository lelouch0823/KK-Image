# 订单与客户操作手册

本文档面向运营、销售支持和管理员，说明当前后台里订单页与客户页的真实操作流。

相关页面：

- 订单管理：`/admin/orders`
- 客户管理：`/admin/customers`

![订单管理](../assets/admin-manual/05-orders.png)

![客户管理](../assets/admin-manual/08-customers.png)

## 1. 权限与页面分工

当前这两页都依赖 `orders:manage` 权限。

订单页负责：

- 筛选订单
- 新建订单
- 导出订单
- 查看详情、状态和履约动作
- 跟进备注和行级处理

客户页负责：

- 搜索客户主档
- 新建和编辑客户
- 查看客户详细资料
- 查看客户关联订单

判断原则：

- 需要推动履约、采购、状态流转，去订单页
- 需要补联系人、公司、标签、备注，去客户页

## 2. 建议的日常处理顺序

1. 先在订单页筛出待处理订单。
2. 进入详情确认订单状态、订单行和采购进度。
3. 需要补沟通背景时，再打开客户页查看客户档案。
4. 涉及缺货和补货时，转到订货总览和采购单页面。
5. 有人员归属问题时，再回到 [销售人员管理](sales-management.md)。

## 3. 订单列表页怎么用

订单页当前支持的常用筛选：

- 销售员
- 订单状态
- 采购状态
- 关键字搜索

当前列表工具条支持：

- 新建订单
- 打开订单统计弹窗
- 导出订单

适合的使用方式：

- 每天先按状态筛待确认、处理中或异常订单
- 某个销售员反馈问题时，先按销售员过滤
- 采购压力大时，用采购状态快速找缺货或未完成订单

## 4. 订单详情里的核心动作

进入订单详情后，当前支持：

- 查看订单时间线
- 添加管理员备注
- 编辑订单
- 删除订单
- 修改订单整体状态
- 对订单行执行履约动作

订单行履约动作当前是：

- `reserve`
- `release`
- `ship`

页面会根据当前订单行数量自动计算可操作上限，并在成功后刷新详情。

建议理解：

- `reserve`
  - 给订单行分配可履约数量
- `release`
  - 释放之前已经预留的数量
- `ship`
  - 确认该行实际出货

如果某个动作按钮不可用，优先看是不是当前行的可执行数量已经为 `0`。

## 5. 订单异常时的排查顺序

### 客户催单，但后台看不出卡在哪

1. 先看订单整体状态。
2. 再看订单行是否已预留、已收货、已出货。
3. 仍不清楚时，转到 [商品与库存管理](product-inventory.md) 对照采购和收货进度。

### 订单能编辑，但履约按钮不能点

常见原因：

- 当前行没有剩余可执行数量
- 已经出货或已取消
- 库存 / 收货进度还没推进到可出货阶段

### 需要导出订单给外部同事

先用筛选缩小范围，再执行导出，避免把无关订单一起带出。

## 6. 客户页怎么用

客户页当前支持：

- 搜索客户
- 新建客户
- 编辑客户
- 打开右侧详情面板
- 查看客户历史订单
- 在无关联订单时删除客户

客户详情里当前分两个标签：

- 基本信息
  - 公司、电话、邮箱、地址、标签、备注
- 历史订单
  - 查看该客户关联订单、销售员和金额

这意味着客户页不是孤立名录，而是订单排查的辅助页。

## 7. 维护客户资料的建议

创建或修改客户时，建议优先补齐：

- 姓名
- 电话
- 公司
- 标签
- 备注

实务建议：

- 客户资料尽量在第一次成单后尽快整理，不要等争议出现再补
- 标签适合标记客户类型、渠道或重要等级
- 备注适合记录交付偏好、特殊要求和历史背景

## 8. 客户无法删除时怎么理解

当前后端会检查客户是否有关联订单。

所以：

- 有历史订单的客户不能直接删除
- 正常做法是保留客户档案，继续作为历史追溯对象
- 只有确认没有关联订单时，才会允许删除

这能避免订单记录失去客户上下文。

## 9. 页面协同建议

订单页和客户页建议这样配合：

1. 先在订单页定位问题单。
2. 如果沟通信息不足，再到客户页补资料。
3. 如果销售归属不清，再到销售员页。
4. 如果履约被库存卡住，再去采购与库存相关页面。
