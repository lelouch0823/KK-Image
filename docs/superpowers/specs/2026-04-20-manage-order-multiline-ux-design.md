# 管理端多行建单 UI/UX 设计

## 背景

当前管理端多行建单已经具备基础能力，但交互仍停留在“单行表单上叠一个多行开关”的阶段：

- `src/components/order/OrderForm.vue` 将模式切换、基础字段、多行编辑、备注和提交动作线性堆叠，缺少总览和工作区分层。
- `src/components/order/OrderLinesEditor.vue` 仅提供连续卡片堆叠，无法快速判断哪些行已完成绑定、哪些行仍有缺口。
- `src/components/order/OrderLineEditor.vue` 以“所有字段全部摊开”为默认形态，信息密度高但认知负担更高。
- `src/components/order/ProductBindingSection.vue` 是整单级商品绑定，不符合“每行独立绑定”的目标。

管理端的真实使用场景是高频录单与偶发录单并存，因此目标不是极致简化，也不是纯粹密集表格，而是“默认引导清晰，同时保留熟练用户速度”的混合型体验。

## 目标

构建一套适合管理端的多行建单主流程，使用户可以在一个订单中高效录入多条商品明细，并在提交前明确掌握：

- 当前订单的总体规模：行数、总件数、图片数、未完成行数
- 每一行是否已绑定商品/规格，是否还缺关键字段
- 当前编辑焦点在哪一行，下一步该做什么
- 提交时是否还存在阻断问题

## 非目标

- 不改动销售端下单 UI
- 不重做订单创建接口契约
- 不在本阶段引入复杂的批量导入、多行拖拽排序、键盘快捷键编排器
- 不改动订单编辑弹窗之外的详情页展示逻辑

## 设计结论

采用“混合型”布局，并以“每行独立绑定”为核心交互模型。

### 1. 页面骨架

管理端建单表单分为三层：

1. 顶部摘要条
2. 中部多行明细工作区
3. 底部固定操作区

这三层都仍然挂在现有 `OrderForm` 与 `OrderCreateModal` 体系内，不引入新的页面级壳层。

### 2. 顶部摘要条

顶部摘要条负责把原本分散在表单各处的上下文集中展示，内容包括：

- 销售员
- 订单状态
- 已上传图片数量
- 明细行数
- 总件数
- 未完成行数

摘要条不是只读展示，它同时承担两类反馈：

- 即时健康度反馈：例如“共 4 行，2 行待绑定”
- 提交前预警：例如“仍有未命名明细，提交后将被拦截”

视觉上使用现有 token 和 `AppCard`/共享 surface，不引入新的局部色板。状态提示仅使用语义 tone。

### 3. 多行明细工作区

多行模式成为管理端主路径，不再只是一个轻量切换项。工作区使用“摘要卡片 + 展开编辑”模式：

- 每行默认先展示摘要态，降低整页信息噪音
- 当前操作行展开后，显示完整编辑区
- 未完成行使用 `warning` 语义强调
- 已完成绑定的行优先显示商品名、SKU、规格和数量，而不是所有字段原样摊开

### 4. 每行独立绑定

每一行明细都可以独立选择商品和规格。绑定行为只影响当前行，不影响整单其他行。

行级绑定规则：

- 行内展示商品选择入口
- 绑定后自动回填 `name/brand/series/sku/size/color/material`
- 绑定确定的字段在行内进入只读或受控显示状态，避免手工改坏快照
- 允许未绑定手填，但卡片显式提示“建议绑定商品”

这意味着现有整单级 `ProductBindingSection` 不能继续作为主入口，需抽取可复用的“行级绑定面板”能力。

### 5. 每行卡片结构

每行卡片包含两个区域：

#### 卡片头摘要

- 行号
- 商品标题或“未命名明细”
- 绑定状态徽标
- 规格摘要
- 数量
- 快捷动作

快捷动作固定为：

- 绑定/重新绑定商品
- 复制上一行
- 新增下一行
- 删除当前行

#### 展开编辑区

展开区按“先绑定、后补充”的顺序组织：

1. 行级商品绑定区
2. 商品补充字段区
3. 数量区
4. 可选备注扩展位（若后续需要）

商品名、SKU、规格字段不再以一整块八宫格静态铺开，而是按优先级组织：

- 绑定后主要展示摘要
- 只有需要人工修正的字段保留编辑控件

### 6. 底部固定操作区

原有备注、交期、取消、提交按钮改为底部固定操作区，保持用户在长表单中也能随时看到提交动作。

该区域同时展示阻断状态：

- 若有未完成行，显示阻断提示
- 若表单满足条件，显示可提交状态

## 交互规则

### 明细新增

- 默认至少保留 1 行
- 新增下一行时，光标焦点进入新行摘要卡片
- 可以从顶部摘要条快速看到总行数变化

### 复制上一行

复制上一行时只复制结构化商品快照和补充字段，不复制危险状态：

- 复制：商品绑定、品牌、系列、SKU、规格等
- 重置：数量回到 `1`

这样可以支持连续录入相似商品，但降低误把大数量直接继承下去的风险。

### 删除行

- 最后一行不可删除
- 删除后若当前展开行被移除，焦点切换到相邻行

### 展开态策略

- 默认只展开当前操作行
- 切换行时收起其他行，避免整页无限增长
- 若某行存在阻断错误，可自动展开该行以便修复

## 验证与错误预防

### 行级校验

每行至少需要满足以下条件之一才算有效：

- 已绑定商品/规格
- 或者具备可提交的手工商品名

同时：

- 数量始终规范化为正整数
- 空白行不计入有效明细
- 未绑定但填了部分字段的半成品行会显示 `warning`

### 整单校验

整单提交前需要满足：

- 销售员必填
- 至少 1 行有效明细
- 至少有 1 张图片
- 没有阻断性的未完成行

### 反馈位置

错误反馈分三层：

1. 行内即时反馈
2. 顶部摘要条聚合反馈
3. 底部提交区阻断提示

避免把所有错误都堆到提交后的 toast 中。

## 架构与文件边界

### 保留并增强

- `src/components/order/OrderForm.vue`
  - 继续担任整体编排容器
- `src/components/OrderCreateModal.vue`
  - 继续承载管理端创建弹窗
- `src/composables/useOrderForm.js`
  - 继续负责提交数据、行归一化和聚合状态

### 新增或拆分

- `src/components/order/OrderLinesSummaryBar.vue`
  - 顶部摘要条
- `src/components/order/OrderLineCard.vue`
  - 行卡片壳层，负责摘要态/展开态和快捷动作
- `src/components/order/OrderLineBindingPanel.vue`
  - 行级商品绑定面板，承接原整单绑定能力

### 可能被弱化或重构

- `src/components/order/OrderLineEditor.vue`
  - 从“大而全编辑表单”转为行内编辑子区
- `src/components/order/ProductBindingSection.vue`
  - 不再作为管理端多行建单主入口；若内部逻辑可复用，则下沉为行级绑定能力

## 数据流

`useOrderForm` 除了继续生成提交 payload，还要额外派生这些 UI 状态：

- `validLineCount`
- `pendingLineCount`
- `totalQuantity`
- `expandedLineId/currentLineIndex`
- `lineValidationState`

这些状态由 composable 提供，组件只做展示和事件派发，避免把判断逻辑散落在多个组件内。

## 测试策略

### 组件测试

- `OrderForm.multiline` 扩展测试
  - 顶部摘要条正确反映行数/总件数/待完善行数
- `OrderLinesEditor`/`OrderLineCard`
  - 展开折叠
  - 复制上一行
  - 删除行
- 行级绑定面板
  - 绑定后字段回填
  - 未绑定警示

### Composable 测试

- `useOrderForm`
  - 派生统计正确
  - 复制逻辑不继承危险数量
  - 空白行和半成品行分类正确

### 回归测试

- 管理端创建单行订单的旧路径不退化
- 管理端编辑弹窗可继续沿用兼容数据结构

## 验收标准

- 管理端打开建单弹窗时，多行模式具备明确的摘要、工作区和底部操作区层级
- 每行都可以独立绑定商品和规格
- 用户无需滚到页面底部也能感知整单状态和提交可用性
- 未完成行在提交前就能被明显识别
- 单行创建与已有提交契约保持兼容
