# 预订单业务简化版说明（面向业务同事）

## 1. 这份说明是给谁的

给销售、运营、采购协同同事快速理解“预订单从创建到采购联动”的核心规则，不涉及代码细节。

## 2. 预订单是什么

预订单就是客户需求单，用于记录“客户想要什么、要多少、希望什么时候到、参考图片是什么”。

业务上可以理解为:
- 销售先收集需求并提交
- 管理端审核确认
- 采购根据已确认的预订单进行补货/下单

## 3. 销售端创建预订单（移动端主流程）

标准流程:
1. 进入“新建预定”
2. 优先选择商品和规格（变体）
3. 填写数量、备注、期望到货时间
4. 上传图片
5. 提交

关键点:
- 选择了商品和规格后，品牌/系列/款号等字段会自动带出并锁定，减少填错。
- 图片必须上传，便于后台和采购快速判断需求。

## 4. 管理端创建预订单（补录流程）

当销售不在线或需要后台代录时，管理端也可直接创建，并可指定销售员与初始状态。

## 5. 状态怎么影响后续协同

对采购最关键的是 `confirmed`（已确认）状态:
- 只有“已确认”的预订单会进入采购建议和“从预订单生成采购单”流程。
- `pending`（待处理）不会进入采购建议。

## 6. 与采购单的联动

采购链路中，预订单会和采购单联动:
- 采购单创建时可直接关联已确认预订单
- 采购单状态推进和收货记录会同步更新预订单采购进度
- 支持部分到货，所以预订单可能先显示“部分到货/部分完成”，再进入全部到货

这保证销售、采购、运营看到的是同一条进度线，而且不会因为只到了一部分货就误判整单全部到货。

补充理解:
- 系统内部已经按“订单行”跟踪采购和到货进度
- 页面上看到的订单采购状态，是对这些行级进度做过汇总后的结果

## 7. 常见业务问题

1. 为什么我创建了预订单，但采购建议里没有？
- 因为订单还没到“已确认”状态。

2. 为什么要先选商品规格？
- 规格决定实际采购与库存口径，不先选规格容易造成错采或重复沟通。

3. 为什么必须传图片？
- 图片是需求确认和售后追溯的重要依据。

## 8. 推荐执行口径（团队可直接采用）

- 销售提交时，优先“商品+规格”标准化录入，减少文本自由发挥。
- 审核同事当天完成 `pending -> confirmed`，避免需求积压。
- 采购只基于 `confirmed` 数据做计划，避免误采。
