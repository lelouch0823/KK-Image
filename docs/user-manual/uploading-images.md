# 文件上传与附件管理

本手册说明当前系统里三种常见上传场景：

1. 管理端文件管理上传
2. Web 销售端订单附件上传
3. 微信小程序销售端订单附件上传

## 先看自己属于哪种场景

如果你是：

- 管理员或运营同事：优先看“管理端上传”
- 手机浏览器里的销售端用户：优先看“Web 销售端上传”
- 微信小程序里的销售端用户：优先看“小程序销售端上传”

## 1. 管理端上传

入口：

- `/admin/files`

典型用途：

- 上传公共素材
- 维护共享空间内容
- 订单补录附件

推荐操作顺序：

1. 进入文件管理页。
2. 先确认当前目录是否正确。
3. 再上传文件。
4. 上传完成后检查文件是否出现在当前列表里。

管理端更适合上传长期复用的正式素材，不适合把临时客户沟通图都堆在一起。

## 2. Web 销售端上传

入口：

- `/sales/:token`

主要发生在：

- 新建订单页上传参考图
- 订单协同过程中补充说明图

推荐操作顺序：

1. 先登录销售端。
2. 进入新建订单页。
3. 先选商品规格，再上传参考图。
4. 等图片状态稳定后再提交订单。

适合上传的内容：

- 客户现场照片
- 款式参考图
- 尺寸或颜色说明图
- 需要后台确认的补充资料

不建议上传：

- 与当前订单无关的历史聊天截图
- 体积很大但业务无关的视频文件

## 3. 微信小程序销售端上传

入口：

- `minisales/`

主要发生在：

- 小程序新建订单页上传图片

推荐操作顺序：

1. 先选好或拍好图片。
2. 进入新建订单页上传图片。
3. 等待上传完成。
4. 确认没有失败项后再提交订单。

小程序上传时要特别注意：

- 图片仍在上传中时不要直接退出当前页
- 如果某张图失败，先删掉或重传，再继续提交

## 当前上传机制

当前三种上传场景底层都走现行上传链路：

- 支持秒传预检
- 文件元数据写入 D1
- 原始对象默认存入 R2
- 上传完成后会触发异步通知、缓存刷新等后续动作

对业务使用者来说，最重要的是：

- 上传成功后不一定每个页面都会瞬间刷新
- 如果刚上传完没看到，先手动刷新当前页面再判断

## 常见问题

### 上传失败

业务侧先做这几步：

- 检查网络是否稳定
- 确认当前页面仍保持登录
- 尝试重新上传一次

如果仍然失败，再交给技术侧排查：

- `DB` 绑定
- `R2_BUCKET` 绑定
- D1 迁移是否完成
- 当前用户是否具备对应权限

### 上传成功但页面没马上显示

- 先手动刷新当前列表或详情页
- 再重新进入当前订单或目录确认

### Web 销售端上传失败

- 确认当前入口确实是 `/sales/:token`
- 确认自己已经登录销售端

### 小程序上传一直转圈

- 先确认网络是否稳定
- 上传未完成前不要离开当前页面
- 如果长时间不结束，删除失败项后重新上传

## 说明

- 当前系统没有默认公开匿名上传首页
- 旧文档里的 `/api/upload` 与首页拖拽上传流程不再适用当前产品
